# API設計規約（汎用テンプレート）

<!-- owner: api-conventions -->

> FastAPI + Pydantic v2 プロジェクト共通。

## エンドポイント命名
- **RESTful**: `/api/{resources}/{id}` （複数形名詞）
- **ネスト**: `/api/groups/{gid}/tournaments/{tid}` （親子関係が明確な場合のみ）
- **アクション**: `/api/tournaments/{tid}/results/publish` （動詞は末尾、リソース操作と区別）

## HTTPメソッド
| メソッド | 用途 |
|---|---|
| GET | 取得（冪等） |
| POST | 作成、または副作用のあるアクション |
| PUT | 全体更新（冪等） |
| PATCH | 部分更新 |
| DELETE | 削除（冪等） |

## レスポンス形式
- **成功（単一）**: Pydantic スキーマ直接返却
- **成功（一覧）**: `PaginatedResponse[T]`（フィールドは各プロジェクトの `app/schemas/common.py` を参照）
- **エラー**: エンベロープ形式（フィールドは各プロジェクトの `app/schemas/common.py` を参照）

## ステータスコード
- 200: 取得・更新成功
- 201: 作成成功
- 204: 削除成功（body なし）
- 400: バリデーションエラー（Pydantic 422 とは別の業務エラー）
- 401: 未認証
- 403: 権限不足
- 404: リソース不在
- 409: 競合（重複など）
- 422: Pydantic バリデーションエラー（自動）

## エラーコード
- `utils/errors.py` にカタログ定義 → ルーターから参照
- エラーコード命名: `{RESOURCE}_{REASON}`（例: `USER_NOT_FOUND`, `ENTRY_DUPLICATE`）
- 新規追加時の追記先はカタログ（`utils/errors.py`）1 か所

## 権限チェック
- 全エンドポイントで認証必須（公開エンドポイントは明示的にデコレーター指定）
- グループ系リソースはメンバーシップ検証必須（IDOR 対策）。テナント分離の機構は各プロジェクトの規範が持つ
- 権限マッピングは各プロジェクトの規範が持つ

## ページネーション
- クエリパラメータ: `offset=0&limit=20`（offset=先頭からのスキップ数 / limit=取得件数）
- 上限: `limit` は 100 程度で制限

## タイムゾーン
タイムゾーンの方針は各プロジェクトの規範が持つ。
