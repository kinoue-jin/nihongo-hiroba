# 多言語対応ルール（汎用テンプレート）

<!-- owner: i18n-policy -->

> 日本語 / 中国語 / その他多言語対応プロジェクト共通。

i18n 辞書にキーが未登録のまま画面表示され、キー文字列（例: `dashboard.title`）がそのまま UI に露出する事故がよく発生する。画面実装時にキー登録忘れを検出する自動チェックが必須。

## ルール（厳守）
1. **全UIテキストはi18nキーで管理**（`ja.json` / `zh.json` / 必要な言語分）
2. **ハードコード日本語/中国語文字列は禁止**（JSX テキスト、`alert()`、`toast()` 引数も対象）
3. **キー形式**: `{screen}.{section}.{item}` （例: `dashboard.header.welcome`）
4. **画面実装完了時に漏れチェック実行**: プロジェクトの check script を実行し、出力 0 件であることを確認する
5. **Agent完了条件にi18nキー漏れチェックを含める**（出力件数 0 が完了条件）
6. **プレースホルダー付き文字列は ICU MessageFormat** を検討（`{count} 件` など）

## 辞書運用
- キー追加時は全言語のJSONを同時に更新する（1言語だけ追加→他言語でキーが欠損するのを防ぐ）
- 翻訳未確定の場合も仮訳で埋める（空文字列は禁止）
